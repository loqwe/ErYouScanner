# v2.0.1 PR #8 短信登录修复

基线为 PR #8 合并提交 `ce8c24f808bd8eb9e0f2274b186d9589d36bd332`，不改动其抖音直播逻辑。版本标识统一为 2.0.1。

- `CreateLoginCaptcha` 改为请求 `/account/ma-cn-verifier/verifier/createLoginCaptcha`，原代码误请求 `/account/ma-cn-passport/app/loginByMobileCaptcha`。
- 仅业务码为 0 且存在非空 `action_type` 时开始服务端指定的倒计时。失败、人机验证或不合法响应不会被当成已发送。
- 恢复原来被 `#if 0` 禁用的短信验证码登录请求，缺失账号或 Token 字段时不会添加空账号。
- 请求开始前在 UI 线程取手机号、验证码等参数；后台任务不访问窗口，结果在 UI 线程处理。请求中禁止重复操作，人机验证可取消。
- HTTP/解析异常和业务错误均有提示及脱敏日志；不记录手机号、短信验证码、Token 或极验凭据，不自动重试发送。

后续复现：真实号码返回 HTTP 200、retcode=-3101，验证参数没有旧版 challenge 字段，导致首个补丁误报内部解析错误。参考米哈游官方在线 SDK，增加 use_v4 分支：v4 使用 gt 作为 captchaId，携带 risk_type 和 session_id 初始化 initGeetest4；v3 仍使用 initGeetest。验证成功后提交原始验证结果，不自动完成验证。内部解析错误不再显示成平台返回码，日志补充无凭据的字段类型和原始业务码。

验证：正确接口真实请求返回 retcode=0，用户确认短信送达；无效号码返回 -3008。独立响应解析回归覆盖成功、错误、v3/v4 验证参数、日志脱敏和不完整登录结果。完整新版 EXE 登录与人机验证流程仍需用户实测。

验证窗口白屏修复：真实 WebView2 对照测试确认，NavigateToString 页面 origin 为 null，存储访问抛出 SecurityError，未生成验证码节点。仅改为本地 HTTPS 虚拟主机后，存储可用，真实极验 SDK 生成 58 个界面节点，脚本错误为零。验证页面仅在本地映射，不运行 HTTP 服务。另修正 WebView2 的物理像素尺寸，增加加载提示、35 秒加载超时、导航和 SDK 阶段的脱敏日志，并清理关闭后的回调，支持再次打开。不自动完成验证或重发短信。

独立 GUI 探针使用项目已有的公开极验应用 ID，不请求短信、不使用账号凭据，检查真实 SDK 显示、页面存储、125% 缩放和关闭后重新打开。该测试不能替代用户完成人机验证后的短信登录验证。
